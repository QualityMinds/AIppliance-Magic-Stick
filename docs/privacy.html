4. Visitor statistics with Umami

We use Umami, an open-source web analytics software, to learn which pages of this website are used and how often. We operate the Umami instance ourselves on Microsoft Azure (section 3): the application runs in Germany West Central (Frankfurt am Main) and its database in West Europe (Netherlands). The data is not passed to an analytics provider.

When a page is loaded, the Umami script sends the following to our Umami instance: the page address without query string, the page title, the referring page, the screen size and the browser language. The connection itself transmits your IP address and user agent. From these, Umami determines the browser, operating system and device type, and the country, region and city using a geolocation database that runs on our instance. The IP address itself is not stored.

To count visits from the same device, Umami forms a session identifier by hashing the IP address, user agent, website, current calendar month and a secret key. The identifier changes every month and is not linked across months. The stored records are pseudonymised: they do not contain your name or IP address, and we do not combine them with other data or try to identify individual visitors.

Umami does not set cookies and does not store an identifier in your browser.

The legal basis is Article 6(1)(f) GDPR. Our legitimate interest is measuring how the documentation and product pages are used so that we can improve them.

Objecting to visitor statistics

You can object at any time. If your browser sends a "Do Not Track" signal, the script sends nothing. You can also switch off statistics for this browser with the button below. It stores the entry umami.disabled in this website's local storage; the entry contains no identifier and is stored only at your request. The setting applies per browser and per website address, so repeat it for each address you use. Clearing this website's data in your browser removes the setting.

6. Retention

Umami records (page views and the pseudonymised session data described in section 4) are deleted 25 months after collection, so that usage can be compared with the same period of the previous year. Error and operating logs of the Umami service are kept for 30 days and database backups for 7 days.

Hosting log data is processed by Microsoft and GitHub under their own retention periods and deletion procedures. Apart from this, we delete personal data when the purpose of processing no longer applies and no statutory retention duties require further retention.
